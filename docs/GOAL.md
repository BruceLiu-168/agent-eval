# Agent Eval 本地框架交付目标

目标：用户在本地安装框架，接入自己的 Agent 与真实数据，完成数据校验、可复现运行、独立判定、版本比较、报告查看和失败样本回流。无需修改框架源码即可接入 Python 函数、HTTP 服务或命令行 Agent。

## 验收条件

1. 可构建并安装 wheel，安装后在仓库外运行 `agent-eval`，内置数据随包分发。
2. `init` 创建可运行项目，`validate` 给出带行号/字段路径的数据错误。
3. 支持 Python、HTTP、command 三种接入；每次执行有超时；错误输出不会变成成功；运行器不把参考答案、rubric 或评测元数据传给 Agent。
4. 同时支持真实 Agent 运行和已有 episode JSONL 的离线评分。业务状态、输出断言、规则、可选 LLM judge 与自定义 grader 均有明确证据和 unknown 状态。
5. 同一数据集上的版本与重复试验可比较；中断后可续跑；配置、数据或实现发生变化时拒绝混入同一运行。
6. 生成 JSON、CSV 和无需联网的 HTML 报告，展示指标分母、证据覆盖、成本缺失、延迟来源、关键违规与逐例证据。
7. 提供独立的本地 HTTP 测试 Agent，覆盖正常、错误、拒绝、超时、幂等和审批场景；验收不依赖付费模型。
8. 线上事件可本地接入、回填业务结果、审核并回流为评测集；同一失败重复接入保持幂等。
9. 自动化测试和隔离安装验收通过，文档给出从演示数据替换为真实数据的完整命令；代码与文档同步 GitHub。

## 本阶段边界

交付形态是本地 Python 框架、CLI 与离线报告。真实业务数据由用户在本地提供；没有真实数据时，框架自测只能证明执行与判定机制，不能证明用户 Agent 的业务质量。模型 API 凭据通过本地环境变量提供，内置验收不调用真实付费模型。

业务成功的真值必须来自独立业务规则、状态观察或专家标签。模拟成本、模拟延迟及测试 Agent 结果始终标明来源。生产多租户门户、托管采集、线上放量与业务补偿属于部署集成范围，不影响本地框架的使用。
