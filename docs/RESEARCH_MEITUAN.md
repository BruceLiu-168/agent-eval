## 五个关键方法与本项目映射

| 文章陈述 | 本项目映射（设计建议） |
| --- | --- |
| **评测完整任务系统及四层能力。** §1.2–1.4 将模型、Prompt、Skill、工具、状态和流程共同视为对象，覆盖结果、过程、效率、风险；观测是基础。 | 绑定完整版本快照；分别统计任务成功、关键行为约束、耗时/成本和风险。Trace 采集可观察调用及环境变化，不要求隐藏思维链。 |
| **业务与模型能力之间搭建任务指标。** §2.1 强调业务结果、系统指标、Agent 能力之间的解释关系。 | 各业务建立“业务目标→任务成功条件→过程诊断指标”映射，平台统一协议，业务保留指标。离线提升是否带来业务收益须经线上实验检验。 |
| **人人一致、人机一致。** §2.2–2.3 建议将模糊指标下钻，把 Rubric 收敛为是/否/未知，并用 unknown 检查标准是否清晰。 | 专家负责规范和裁决，人工独立标注形成校准集；Judge 输出判定与证据，unknown 进入复核，不能视为通过。 |
| **Good/Bad Case 驱动数据飞轮。** §2.4 给出采集、清洗、评测、质检、分析归因五环节，连接线上 AB 和持续观测；先从核心场景、少量指标起步。 | 线上案例经脱敏、补全上下文和复核后进入版本化离线集，再回归、发布和观测。同时保留随机代表性样本，避免只看失败样本；后一句为本项目补充。 |
| **长程任务采用行为与环境结果判定。** §3.2.2 使用 prompt / expected_behavior / trace 三元组；附录区别 Trial、Grader、Outcome，强调真实环境结果区别于声称完成。 | Case 包含初始环境、约束和成功断言；最终状态证明完成，Trace 支持归因。多次 Trial 观察随机性，历史记录回放与重新执行分别建模。 |

## Offline / Online 闭环

本项目流程：线上 Trace 与业务反馈 → 抽样、清洗、脱敏、去重 → Good/Bad Case 候选 → 专家复核与 Rubric 校准 → 版本化离线集 → 候选版本评测、归因与历史回归 → 发布门禁 → 灰度或线上实验 → 业务收益与风险观测 → 新一轮案例沉淀。

平台提供 Trace、Case、Dataset、Experiment、Trial、Evaluator、Annotation、ReleaseGate 的共同协议；业务提供成功条件、工具适配、环境夹具、专家知识及风险规则。保留多种有效完成路径，避免将唯一参考轨迹当成唯一成功方式。

## 披露边界

§3.2.5 列出全链路回放、Case 管理、执行沙箱、AI 评测、报告归因、回归和准入准出门禁，原文用语是“至少应该具备”：这是基础设施建议，不能写成美团已全部上线的能力清单。

材料未提供可直接部署的完整开源平台、通用门禁阈值或完整内部架构。本项目不是美团内部系统的复刻；协议、选型、抽样方法及门禁是本项目设计。
